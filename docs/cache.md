# Cache
Кэширование данных в ZYNQ. В интеграторе и в обратной связи в плате HP получается следующая ситуация: доступ к памяти нужен из трех разных мест: порт ACP, к которому подключен PCIE, первое и второе ядро. Схема показана на рисунке 1. Описывая схему, можно выделить, что:
-  точкой когерентности при этом является не DDR3 паямить а L2 кэш
-  у каждого из ядер помимо этого есть еще свои L1 кэши для данных и инструкций
Чтобы достичь когерентности данных между тремя источниками, нужно:
## ACP
Со стороны порта нужно установить AXI сигналы AxUSER и AxCACHE. AxUSER устанавливается в блочном дизайне, в инстансе ZYNQ7 Processing System, по пути  PS-PL Configuration/ACP Slave/Tie off AxUSER. Если утановлен AxUSER, AxCACHE определяют когерентность транзакции. Биты показаны на рисунке 2. WA/RA устанавливают, может ли танзакция добавлять данные в кэш в случае промаха. C отвечает за когерентность транзакции. B определяет режим кэша: write-throught или write-back. Для обеспечения когерентности данных, достаточно установить только бит C.
## U-Boot
Во время работы U-Boot для обеспечения когерентности со вторым ядром достаточно dcache flush после после записи памяти. Однако, операции invalidate у dcache нет, а flush записывает данные в L2 кэш из своего L1, поэтому не очень понятно, как обеспечивается когерентность в случае записи данных в L2 вторым ядром.
## Bare-metal
Для обеспечения когерентности L1 и L2 кэшей вторым ядром исмользуются операции flush и invalidate. После записи - flush, которая запишет данные из L1 в L2, перед чтением - invalidate, которая пометит L1 кэш как невалидный и приведет к обращению к L2 при дальнейших операциях.
